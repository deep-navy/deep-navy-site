<section class="page-hero"><div class="shell"><span class="eyebrow">Integration reference / GitHub</span><h1>Repository authority remains with the GitHub organization.</h1><p>An organization owner installs the GitHub App, chooses available repositories, and can revoke the installation in GitHub. deep navy records a separate customer repository selection.</p><div class="page-meta"><span>GitHub App</span><span>Installation tokens</span><span>Versioned selection</span></div></div></section>

<section class="content-section" aria-labelledby="github-path"><div class="shell content-grid"><header><span class="eyebrow">Request path / 01</span><h2 id="github-path">Installation is bound to the signed-in organization.</h2></header><ol class="timeline"><li><div><h3>Request link</h3><p>The authenticated customer app asks GitHubService for a server-generated installation URL bound to the current deep navy organization.</p></div></li><li><div><h3>Review on GitHub</h3><p>A GitHub organization owner checks the App identity, permissions, and repository access on a GitHub-owned page.</p></div></li><li><div><h3>Validate callback</h3><p>The platform validates the callback state and records the installation-to-organization mapping.</p></div></li><li><div><h3>Select scope</h3><p>The customer records selected repositories or the all-accessible mode using the current selection version.</p></div></li><li><div><h3>Mint token</h3><p>Server-side services request a short-lived installation token when a scoped GitHub operation is required.</p></div></li></ol></div></section>

<section class="content-section" aria-labelledby="github-controls"><div class="shell content-grid"><header><span class="eyebrow">Control register / 02</span><h2 id="github-controls">Credential and repository boundaries.</h2></header><div class="data-table-wrap"><table class="data-table"><thead><tr><th>Control</th><th>Enforcement point</th><th>Customer action</th></tr></thead><tbody><tr><td>App identity and permissions</td><td>GitHub installation page</td><td>Organization owner reviews before install</td></tr><tr><td>Available repositories</td><td>GitHub App installation</td><td>Organization owner selects or updates access</td></tr><tr><td>deep navy repository scope</td><td>Platform API repository selection</td><td>Authorized member saves the selection</td></tr><tr><td>Credential lifetime</td><td>Server-side installation-token minting</td><td>No credential handling in the browser</td></tr><tr><td>Revocation</td><td>GitHub organization settings</td><td>Owner suspends or removes the App</td></tr></tbody></table></div></div></section>

<section class="content-section" aria-labelledby="github-record"><div class="shell content-grid"><header><span class="eyebrow">Delivery record / 03</span><h2 id="github-record">Work remains reviewable in GitHub.</h2></header><div class="prose"><p>The team uses the installation for scoped issues, commits, checks, reviews, and pull requests. deep navy associates those artifacts with team and product-work identifiers.</p><p>If the platform cannot issue a verified installation link or confirm the callback, onboarding remains incomplete. See the <a href="{{ '/security/' | relative_url }}">security request path</a> for the surrounding trust boundaries.</p></div></div></section>
