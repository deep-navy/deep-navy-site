<section class="page-hero"><div class="shell"><span class="eyebrow">Security by boundary</span><h1>Autonomous work inside explicit limits.</h1><p>Deep Navy is designed around isolated customer runtimes, short-lived access, server-side authorization, and human approval for protected actions.</p><div class="page-meta"><span>Architecture statement</span><span>Updated July 17, 2026</span><span><a href="mailto:security@deep.navy">security@deep.navy</a></span></div></div></section>

<section class="content-section"><div class="shell content-grid"><header><span class="eyebrow">Core controls</span><h2>Defense across identity, runtime, and delivery.</h2></header><div class="feature-cards"><article class="feature-card"><span class="number">01</span><h3>Identity and authorization</h3><p>Cognito authenticates users. The API—not the static site—enforces customer, organization, repository, team, and admin authorization.</p></article><article class="feature-card"><span class="number">02</span><h3>Runtime isolation</h3><p>Each customer team receives a dedicated Kubernetes namespace and OpenClaw Gateway. Agent workspaces are separated within that team runtime.</p></article><article class="feature-card"><span class="number">03</span><h3>Credential handling</h3><p>Browsers never receive AWS, GitHub App, Stripe, OpenClaw, LiteLLM, or Langfuse secrets. GitHub installation tokens are short-lived.</p></article><article class="feature-card"><span class="number">04</span><h3>Approval policy</h3><p>Sensitive operations can require an explicit, authorized human decision that is preserved in the audit model.</p></article></div></div></section>

<section class="content-section"><div class="shell content-grid"><header><span class="eyebrow">Customer data path</span><h2>The static site is not a trust boundary.</h2></header><div class="prose"><p>The public and customer site is static Jekyll content hosted by GitHub Pages. It contains public runtime coordinates only: API origin, Cognito domain, public client ID, callback URLs, and RPC paths.</p><p>Authenticated requests go to the versioned platform API. Services authenticate, authorize, validate, and persist the operation server-side. The API or stream service proxies runtime visibility; OpenClaw Gateway credentials are never exposed to the browser.</p><div class="callout"><strong>Token storage in the early-access shell</strong><p>The OAuth code verifier and state are transient in <code>sessionStorage</code>. Access and ID tokens remain in memory and are not written to <code>localStorage</code>. A page refresh intentionally ends the browser session.</p></div></div></div></section>

<section class="content-section"><div class="shell content-grid"><header><span class="eyebrow">What we do not claim</span><h2>Trust requires accurate status.</h2></header><div class="prose"><p>Deep Navy does not claim certifications, audit reports, penetration-test coverage, uptime commitments, or generally available incident processes that have not been completed. Current and planned controls are separated in the <a href="{{ '/trust/' | relative_url }}">trust center</a>.</p><h3>Report a vulnerability</h3><p>Send a concise report to <a href="mailto:security@deep.navy">security@deep.navy</a>. Include the affected surface and reproduction steps, but do not access another customer's data, disrupt service, or publish the issue before coordinated resolution.</p><p>For sensitive material, first request an encrypted reporting channel. We will acknowledge receipt and provide a coordination contact.</p></div></div></section>
